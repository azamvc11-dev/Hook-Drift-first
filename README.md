# Hook Drift

Аркада в стиле Stickman Hook: цепляйся крюком за точки, раскачивайся, отпускай в нужный момент,
рикошеть от блоков-препятствий, открывай скины за дистанцию.

## Что нового в этом обновлении

### Стало легче
- Гравитация чуть слабее, а дальность автозацепа крюка увеличена — после отскока
  от блока гораздо проще успеть зацепиться за следующую точку.
- Рикошет от препятствий смягчён: раньше он мог отправить игрока резко вниз и
  не оставить шанса на восстановление — теперь отскок никогда не швыряет вниз
  сильнее умеренной скорости.
- Добавлены **батуты** — блоки у нижней границы экрана (со стрелками вверх),
  появляются регулярно, примерно раз в 150–300м пройденной дистанции. Столкновение
  с ними подбрасывает игрока вверх и придаёт разгон вперёд — это помощь, а не опасность.

### 🕷️ Секретный режим Паука
Открывается автоматически, когда личный рекорд дистанции достигает **3000м**. После этого
на стартовом экране появляется переключатель «Режим Паука: ВКЛ/ВЫКЛ». Механика меняется:
вместо раскачивания на тросе стикмен летит **прямо** под тем углом, под которым зацепился,
а долетев до точки крюка — автоматически отцепляется и продолжает лететь дальше. Играть
становится заметно легче: нет риска не рассчитать мах и врезаться в блок на развороте.
Переключатель можно выключить в любой момент — прогресс разблокировки при этом сохраняется.

### 🏆 Таблицы лидеров и аккаунты
Полностью переехали на Supabase — подробности и инструкция по настройке ниже, в разделе
[«Аккаунты, время игры и таблицы лидеров»](#аккаунты-время-игры-и-таблицы-лидеров-supabase).

### 📺 Yandex Games SDK (реклама)
Добавлен `js/yandex.js` — подключает `YaGames.init()`, сигнализирует площадке о готовности
(`LoadingAPI.ready()`), и показывает:
- **межстраничную рекламу** — не после каждой смерти подряд, а раз в 3 попытки, чтобы не
  раздражать игрока;
- **рекламу за вознаграждение** — кнопка «📺 Продолжить (реклама)» на экране проигрыша даёт
  один повторный шанс за забег, если посмотреть ролик целиком.

Вне площадки Яндекс Игр (обычный браузер, Telegram, PWA на iPhone) скрипт SDK просто не
загружается по таймауту, и все вызовы становятся no-op — игра не ломается и ничего не просит.

**Как опубликовать на Яндекс Играх:**
1. Зарегистрируйся как разработчик на [yandex.ru/games/dev](https://yandex.ru/games/dev/)
2. Собери zip-архив **из содержимого** папки `hookdrift` (файлы в корне архива, не сама папка) —
   `index.html` должен лежать в корне zip.
3. В личном кабинете создай новую игру → загрузи zip как черновик → протестируй через
   тестовую ссылку (там `YaGames` уже доступен по-настоящему, и реклама/лидерборд заработают).
4. После проверки — отправь на модерацию.

Технические требования Яндекса (ориентация, лимит размера архива и т.п.) периодически
меняются — сверься с актуальной документацией в личном кабинете разработчика перед сдачей.

## Аккаунты, время игры и таблицы лидеров (Supabase)

Старый самописный Node-бэкенд (`server/`) убран — его полностью заменяет **Supabase**:
готовая база данных + встроенная аутентификация, бесплатного тарифа с запасом хватает
для такого проекта.

### Что это даёт
- **Регистрация по нику и паролю, без почты.** Под капотом — настоящая Supabase Auth
  (пароли хранятся правильно, хешированные), но email синтетический (`ник@hookdrift.game`) —
  игрок его никогда не видит. Ник уникален автоматически.
- **Наигранное время.** Считается только пока реально идёт забег (не когда игра лежит на
  паузе/экране меню), отправляется на сервер каждые ~20 секунд и при уходе со страницы.
  Отображается в аккаунт-панели на стартовом экране.
- **Две таблицы лидеров** — по дистанции и по времени игры, переключаются вкладками.
  По умолчанию показывают топ-10. Кнопка **«Подробнее»** открывает список побольше
  (до 200 игроков), с описанием таблицы и отдельно — твоё текущее место и результат,
  даже если ты не попал в показанный список.

Рекорд для скинов/секретного режима Паука по-прежнему считается локально на устройстве
(через `window.storage`) и работает без аккаунта — это осознанно, чтобы игра оставалась
полностью играбельной офлайн/без регистрации. Аккаунт нужен только для попадания в
общую таблицу лидеров и учёта времени.

### Настройка (5 минут)
1. Зарегистрируйся на [supabase.com](https://supabase.com) → создай новый проект (бесплатный тариф).
2. В панели проекта: **SQL Editor → New query** → вставь целиком содержимое файла
   [`supabase/schema.sql`](supabase/schema.sql) из этого архива → **Run**.
   Это создаст таблицу `profiles`, политики безопасности (RLS) и функции для
   безопасного обновления рекорда/времени.
3. **Важно:** зайди в **Authentication → Providers → Email** и убедись, что переключатель
   **"Confirm email" выключен**. Иначе Supabase попытается отправить письмо на
   синтетический адрес — а получать его будет некому, и регистрация не завершится.
4. **Project Settings → API** — скопируй **Project URL** и **anon public** ключ.
5. Впиши их в `js/supabase-config.js`:
   ```js
   window.SUPABASE_CONFIG = {
     url: 'https://твой-проект.supabase.co',
     anonKey: 'eyJhbGciOi...' // anon-ключ безопасно класть в клиентский код
   };
   ```
6. Готово — обнови страницу, на стартовом экране появится карточка аккаунта.

Если оставить `url`/`anonKey` пустыми — вся эта система просто не активируется, игра
работает как раньше, локально, без аккаунтов и без онлайн-таблиц.

## Настройки (язык + ориентация экрана)

Кнопка ⚙️ (в HUD, сверху) открывает экран настроек:
- **Язык интерфейса** — русский/английский, переключается мгновенно и сохраняется между сессиями.
- **Ориентация экрана** — Авто / Вертикально / Горизонтально. Честно: настоящая блокировка
  ориентации (`screen.orientation.lock`) работает только в полноэкранном режиме и только в части
  браузеров (в основном Android Chrome) — в Safari на iOS её вообще нет. Настройка пытается
  включить её там, где это реально поддерживается, а там, где нет — просто ничего не делает
  и не мешает игре. Мы сознательно отказались от идеи эмулировать поворот через CSS-трансформацию:
  это ломало адаптивную вёрстку (браузер считает медиа-запросы и vw/vh от реального, а не
  визуально повёрнутого экрана), из-за чего часть интерфейса становилась огромной или обрезанной.

## Адаптивность на телефонах — важные исправления

- **Кнопки не реагировали на тач.** `touchend` раньше глобально перехватывался на всём `window` с
  безусловным `preventDefault()` — это глушило синтетический `click`, который браузер генерирует
  после тапа, и любые кнопки интерфейса переставали на что-либо реагировать. Теперь перехват
  работает только для касаний, начавшихся непосредственно на игровом canvas.
- **Элементы HUD и скины были слишком крупными на маленьких экранах.** Раньше многие размеры были
  захардкожены в пикселях и подгонялись отдельными медиа-запросами по шагам. Теперь иконки в HUD
  (счёт, кнопки музыки/звука/настроек) и свотчи скинов используют `clamp()` — они плавно
  масштабируются под ширину экрана без резких скачков и без риска съехать при нестандартных
  разрешениях. Десктопная вёрстка при этом не тронута: `clamp()` на широких экранах упирается в
  тот же максимум, что был раньше.

## Большое обновление: адаптив, стикмен, музыка, частицы, скины

### Адаптив — настоящая причина мелких элементов на телефоне
Раньше расстояния между точками крюка, размеры блоков/батутов и игрока были в фиксированных
пикселях, откалиброванных под десктопный экран (~1280px и шире). На узком телефонном экране
это означало, что часть игрового мира буквально не помещалась в видимую область. Теперь при
каждом ресайзе считается `worldScale` (от реальной ширины экрана) и от него зависят: радиус
игрока и точек крюка, дистанция автозацепа, промежутки между точками, размеры блоков и батутов,
скорость частиц. На широких десктопных экранах `worldScale` упирается в 1 — там ничего не
изменилось. Плюс добавлено защитное `overflow:hidden` на уровне `#wrap`, чтобы в принципе
исключить горизontal-скролл, даже если что-то где-то вылезет.

### Стикмен с суставами и анимацией
Раньше персонаж — просто кружок с двумя статичными палочками-ногами. Теперь это процедурно
анимированный стикмен: голова, торс, две руки и две ноги на суставах.
- Ноги переступают/болтаются в полёте по циклической анимации.
- Когда висишь на крюке или летишь в режиме Паука — ближняя рука тянется точно к точке
  зацепа (визуальная IK), вторая волочится позади.
- В свободном падении руки взмахивают, тело слегка наклоняется по направлению скорости
  (лёгкий "спайдерmenовский" крен).
- Изредка моргает — маленькая деталь для живости.

### Амбиентные частицы
В воздухе игрового мира медленно плывут мелкие светящиеся частицы (независимо от частиц
столкновений/крюка) — создают ощущение глубины и атмосферности фона.

### Больше скинов
Список расширен с 6 до 12: Классик, Неон, Сакура, Магма, Токсик, Королевский, Золото, Лёд,
Пустота, Закат, Фантом, Легенда — от 0 до 4000м личного рекорда.

### 5 музыкальных жанров + автосмена
В настройках (⚙️ → «Музыка») можно выбрать один из пяти процедурно генерируемых жанров:
Спокойная, Фонк, Электро, Чиптюн, Эмбиент — у каждого своя гамма, темп, тембр и (где уместно)
ритм-секция (бас-бочка + хай-хэт), всё синтезируется на лету через Web Audio, без аудиофайлов.
Переключатель «Автосмена жанра» заставляет игру самостоятельно менять жанр каждые ~75 секунд;
если выключен — играет только выбранный жанр постоянно. Выбор сохраняется между сессиями.

## Ориентация экрана — исправлено по-настоящему

Раньше выбор «Горизонтально»/«Вертикально» в настройках почти ничего не делал на iPhone (Safari
не поддерживает `screen.orientation.lock`), а попытка эмулировать это через CSS-разворот ломала
вёрстку — потому что браузер всегда считает `vw`/`vh` и медиа-запросы от **реального**, а не
визуально повёрнутого экрана.

Теперь это сделано правильно: `js/settings.js` сам считает "эффективные" (с учётом принудительного
разворота) ширину и высоту и публикует их как CSS-переменные `--evw`/`--evh` — вся вёрстка в
`css/style.css` использует `calc(var(--evw)*N)` вместо `Nvw`. Брейкпоинты (узкий/короткий/широкий
экран) тоже больше не `@media`, а классы на `<html>`, которые выставляет JS от тех же эффективных
размеров. Благодаря этому:
- Выбор ориентации в настройках применяется **мгновенно**, не дожидаясь физического поворота устройства.
- Если выбрано «Вертикально», а телефон физически повернули в landscape — интерфейс **остаётся**
  в портретной раскладке (и наоборот), вместо того чтобы следовать за реальным поворотом.
- Стартовое меню теперь всегда помещается по высоте без необходимости скроллить в поисках кнопки
  «Начать» — раскладка сжимается через те же JS-брейкпоинты.

## Стикмен стал по-настоящему объёмным

Раньше — тонкие линии-скелет. Теперь — толстые "мясистые" капсулы вместо линий, залитый скруглённый
торс вместо палочки, увеличенная голова и большие выразительные глаза (белок + зрачок + блик),
ближе к референсу, который прислали. Суставы и анимация (переступающие ноги, рука, тянущаяся
к точке крюка, лёгкий наклон по direction of travel) остались.

## Частицы-шлейф в стиле Geometry Dash

Позади игрока теперь постоянно отлетают мелкие частицы цвета текущего скина — не только при
столкновениях/крюке (это осталось), а буквально каждый кадр движения, как хвост в Geometry Dash.

## Анимации через animate.css

Подключена библиотека [animate.css](https://animate.style/) через CDN. Переходы между экранами
(меню, настройки, вход, таблицы лидеров, экран поражения) используют её keyframe-анимации
(`fadeIn`, `fadeInUp`, `fadeInDown`, `zoomIn`, `shakeX` и т.д.) — с ускоренным таймингом
(`animate__faster`), чтобы не тормозить навигацию. Свотчи скинов появляются с лёгким
каскадным `zoomIn`, кнопки музыки/звука дают тактильный `pulse` при нажатии, а заголовок
экрана поражения встряхивается (`shakeX`) при каждой смерти.

## Скины стали "костюмами", вся игра — чёрно-бело-серая

По референсу (Stickman Heroes) переделал систему скинов: раньше скины различались цветом тела,
теперь — силуэтом/аксессуаром поверх базового стикмена, а вся палитра игры (фон, крюки, блоки,
батуты, частицы, интерфейс, иконка) переведена в чёрный/белый/серый.

12 костюмов (по мере роста рекорда): Классик (без аксессуара) → Повязка → Ниндзя (маска) →
Демон (рога) → Рыцарь (шлем) → Разведчик (кепка) → Мистик (капюшон) → Киборг (визор) →
Панк (ирокез) → Дворянин (плащ) → Король (корона) → Легенда (нимб). Каждый аксессуар рисуется
процедурно в `game.js` (свитч по `skin.accessory`) поверх объёмного стикмена — не картинки,
а векторные фигуры, которые вращаются/масштабируются вместе с персонажем и его анимацией.

## Что изменилось по твоим правкам

- **Проигрыш только при падении вниз.** Если стикмен улетает вверх за пределы экрана — ничего
  страшного, камера просто следует за ним. Смерть засчитывается, только когда он реально
  исчезает за нижним краем экрана.
- **Блоки-препятствия.** Между точками крюка иногда появляются блоки с предупреждающей штриховкой —
  при столкновении стикмен рикошетит (отражается от поверхности с небольшим ускорением), а не гибнет.
- **Скины.** Открываются автоматически по личному рекорду дистанции: 0 / 150 / 400 / 700 / 1200 / 2000м.
  Выбираются на стартовом экране, прогресс сохраняется между сессиями.
- **Звук и музыка.** Полностью синтезируются в браузере через Web Audio API — отдельных
  аудиофайлов нет вообще, поэтому ничего не нужно догружать и всё работает офлайн.
  Кнопки 🎵/🔊 в правом верхнем углу включают/выключают их по отдельности.
- **Раздельные файлы** — html/css/js разложены по своим файлам и папкам, как просил.

## Как запустить локально

Файлы должны открываться через веб-сервер (не просто двойным кликом по index.html) —
иначе service worker и PWA-манифест не заработают:

```bash
cd hookdrift
python3 -m http.server 8080
# затем открой http://localhost:8080
```

Или любой другой статический сервер (`npx serve`, VS Code Live Server и т.д.)

## Установка на iPhone (офлайн-игра)

Service worker и manifest.json дают полноценную PWA — но для их работы файлы нужно
открыть по **https** (или на localhost). Просто открыть index.html как локальный файл
в Safari через AirDrop/Файлы не даст install prompt и офлайн-кэш работать не будет —
таковы ограничения iOS Safari.

Поэтому:

1. Залей всю папку `hookdrift/` на бесплатный статический хостинг с https:
   - **GitHub Pages** — создай репозиторий, включи Pages в настройках, готово.
   - **Netlify** / **Vercel** — перетащи папку на их сайт, получишь https-ссылку за минуту.
   - **Cloudflare Pages** — аналогично.
2. Открой полученную ссылку **в Safari** на iPhone (обязательно Safari, не Chrome —
   только Safari умеет добавлять PWA на домашний экран на iOS).
3. Нажми кнопку «Поделиться» (квадрат со стрелкой вверх) → **«На экран Домой»**.
4. Иконка Hook Drift появится на домашнем экране. При первом запуске (с интернетом)
   service worker закэширует все файлы — после этого игра открывается и работает
   полностью без интернета, в полноэкранном режиме, без адресной строки Safari.

## Управление

- **Тап / клик** — выпустить крюк в ближайшую точку впереди
- **Удержание** во время раскачивания — подтягивать трос (набор скорости)
- **Отпускание** — отцепиться и лететь по инерции
- Столкновение с полосатым блоком — рикошет в сторону, без урона
